## 3. Findings
Severity: P0 critical · P1 high · P2 medium · P3 low. "Before prod" = acceptable for a dev demo only.

### Security / operations
- **F-01 (P1 now; P0 before any real use) Dev credentials are public.** The repo is public (`DB/GitHub: visibility=public`) and the live site is public; `teacher@neuromind.test` and `learner*@neuromind.test` use the default password `NeuroMind-dev-2026!`, which is hard-coded in `scripts/create_dev_users.py` and `frontend/e2e/helpers.ts` and was posted in chat. Anyone can sign in as the teacher and list learners. No real learner data exists yet (0 attempts/submissions in DB). Violates §3.1 ("remove or rotate development test accounts"). *Fix:* rotate the passwords now, read the password only from env (no default), keep the repo private or purge the defaults, treat Git history as burned.
- **F-02 (P1) Service-role key was pasted into chat.** Rotate in Supabase and update the Vercel `SUPABASE_SERVICE_ROLE_KEY`.
- **F-03 (P2) Auth hardening off/unknown.** Supabase advisor WARN: leaked-password protection disabled. Whether open self-signup is enabled is UNVERIFIED (default is on; new users correctly become `learner` via the profile trigger, but anyone could register). *Fix:* enable leaked-password protection; decide signup policy; add password reset (§20).
- **F-04 (P2) Defence in depth.** `anon` and `authenticated` hold SELECT/INSERT/UPDATE grants on every public table (Supabase default); protection rests only on RLS having no write policies. *Fix:* revoke unneeded grants in a migration.
- **F-05 (P2) No audit events.** `audit_logs` has 0 rows and no code writes to it (§15.3; US-02 "403 + safe audit event"). Denied access, role changes, submission lifecycle, publication are unlogged.
- **F-06 (P2) Observability.** No structured/server logs, no readiness endpoint beyond `/health`, no metrics for queue depth/latency (§14.3). Request IDs exist in error bodies only.
- **F-07 (P2) Sign-out leaves client cache.** `AuthProvider.signOut` does not clear the TanStack Query cache; a second user on the same browser can briefly see the previous user's cached courses/progress/teacher results (§3.1 "clear sensitive client state"). SRC.
- **F-08 (P2) Expired session handling.** A 401 from the API shows a generic error; it does not route to sign-in (§18). SRC.

### Assessment / policy (needs product-owner decision — not silently changed)
- **F-09 (P1) Attempt-limit conflict.** Requirements §6.2: "unlimited practice attempts". The seeded exercise has `max_attempts = 5` (DB) and the API enforces it (`ATTEMPTS_EXHAUSTED`), following the earlier pack's API example. *Decision needed:* unlimited (with abuse/rate limits) vs capped.
- **F-10 (P1) Best-valid-score, hints, remediation, appeals, teacher feedback are not implemented** (§6.2, §9.2). Results show the latest attempt only; "remediation" is a generic "read the feedback" message; no hint model; no teacher feedback entity; no appeal flow. Teachers correctly have no endpoint to edit scores (SRC).
- **F-11 (P1) Evidence record incomplete (GRD-008, §6.3).** `lab_submissions` has no grader/test-suite/content-version columns (DB), no max score/threshold snapshot, no per-criterion result rows, no hint use, no correlation ID. Historical meaning of a score is not preserved if tests change.
- **F-12 (P1) Teacher scope is global.** Any teacher/admin sees every learner; there is no cohort/assignment model (§3, §9.1; open decision "Teacher assignment"). Lists are unpaginated (§12.1), no filters/search, and the results page shows raw ID suffixes instead of lecture/checkpoint titles. Teacher "evidence" is limited to status/score/test counts; no feedback publication, no learner-detail or submission-detail screens.

### Core workflow
- **F-13 (P1) Official grading does not work on the hosted site and is unproven anywhere.** The Docker grader exists only for local use; hosted submissions return a recoverable "grader unavailable". Background grading uses FastAPI `BackgroundTasks`, which may not complete on Vercel serverless. The Docker runner, image build, limits, cleanup and `docker kill` timeout path have never been executed (SAN-001…012 UNVERIFIED). Queue/backpressure is a 2-slot semaphore only (SAN-012).
- **F-14 (P1) End-to-end journeys A–E never executed** (§19.2). Specs exist and typecheck (`frontend/e2e`). First live run will likely expose integration bugs: the PostgREST repository, Supabase token check, Monaco/Pyodide CDN loading and the manually created auth users have never been exercised against the real services.
- **F-15 (P2) Coding lab gaps (§7.1).** No Reset-to-starter; work is not saved/restored (a refresh resets to starter code); no unsaved-work warning; stdout and stderr share one pane; no error-line markers; Pyodide limits are output cap + 5 s wall-clock only; no unsupported-package messaging.
- **F-16 (P2) Missing screens (§20).** No course overview/module view (dashboard shows the first course's lectures only), no standalone grading-status, remediation or completion-summary screen (no "next allowed step"), no profile, no authoring, no password reset. Progress bar shows segment position, not separate media/checkpoint/lab/mastery progress (§4.4).
- **F-17 (P3) Video.** Always-visible "I've finished this video — continue" lets a learner skip any video (acceptable only because videos are not gates; conflicts with "respect segment boundaries" if policy changes). `<track kind="captions">` has no source, so no captions exist (§14.2). Media URL is an external sample clip; CORS/range/R2 not tested.
- **F-18 (P2) Content.** All lecture content (title is from the earlier API spec; objectives, questions, tests, 5-second videos) is placeholder; the 60-minute template is not reproduced; the exact sample-lecture title/objectives were never verified against a curriculum source (§25).

### Quality / compliance
- **F-19 (P2) Accessibility and responsiveness unverified** beyond the sign-in page (§14.2). Stacking CSS exists below 900 px but no run at 390/768/1366/1440 on the lecture or lab; no contrast, 200 % zoom or screen-reader pass.
- **F-20 (P2) Capacity claims.** No portal or grading load tests (§16, §19). Docs disagree on target (100 in the pack, ≈200 here); neither is evidenced.
- **F-21 (P3) Version drift.** Tested on Python 3.13 / pnpm 10 vs documented 3.12 / 9.15.4; Vercel's Python runtime is chosen by Vercel. No CI pipeline exists (§17).
- **F-22 (P3) Privacy/child safety, retention, backup/restore, rollback** are undocumented (§15, §21, §26).

2. Run the local stack per README and execute journeys A–E; fix what breaks (F-13, F-14).
3. Owner decisions: attempt policy, best-score + hint formula, teacher assignment model, retention (F-09, F-10, F-12).

5. Lab usability: save/restore work, reset-to-starter, unsaved warning (F-15); responsive and keyboard checks at the five required widths (F-19).
6. Load tests and sandbox adversarial tests before any capacity claim (F-20, SAN tests).
